## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 모의 인터넷뱅킹 서비스 - 관리자 콘솔 |
| 왜 하는가 | 고객 서비스와 분리된 백오피스 시스템과 감사 추적 구조를 구현해 보기 위해 |
| 무엇을 하는가 | 회원·계좌·거래·상품·대출 조회와 운영 조치(이용 제한, 동결, 상품 등록), 활동 로그 |
| 배경 | 승인 판정은 시스템 규칙이 처리하는 은행 업무이므로, 관리자는 운영·모니터링을 맡는다 |
| 목표 | 핵심 기능 4주차 완료, 상태 변경 기록 누락 0건 |
| 기대 효과 | 백오피스 설계, 권한 분리, 감사 로그 경험 |
| 핵심 사용자 | 은행 관리자 (역할별 구분 검토 중) |
| 벤치마킹 | 일반 관리자 페이지 구성, 은행의 지급정지·이용 제한·감사 로그 개념 |
| 기술 스택 | Java, Spring Boot, Spring Security, MyBatis 또는 JPA, Oracle, Thymeleaf, REST API, Redis, WebSocket, Spring 이벤트·비동기 처리, (선택) Spring Mail |

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 판정 | 회원가입, 계좌 개설, 대출 등의 승인 여부를 정하는 일. 시스템 규칙이 한다 |
| 운영 조치 | 관리자가 하는 상태 변경 (이용 제한, 잠금 해제, 동결/해제, 상품 판매중지) |
| 이용 제한 | 관리자가 회원의 로그인·거래를 막은 상태 (정지) |
| 계정 잠금 | 비밀번호 연속 오류로 시스템이 로그인을 막은 상태 |
| 동결 | 관리자가 계좌의 출금·이체를 막은 상태 |
| 계좌 상태 이력 | 계좌 상태가 바뀔 때마다 남는 기록 (변경 전후, 변경 주체, 사유, 일시) |
| 관리자 활동 로그 | 관리자가 한 모든 상태 변경 기록 (감사 로그) |
| 변경 주체 | 상태를 바꾼 쪽: 고객 / 시스템 / 관리자 |
| 이상거래 대응 담당자 | 탐지 건을 받아 확인하고 고객에게 연락하는 관리자 (운영 관리자 역할) |
| 처리 단계 | 탐지 건의 진행 상태: 미확인 → 담당 확인 → 고객 연락 중 → 정상 거래 확인 / 사기 의심 조치 |

## 3. 사용자(액터) 정의

| 액터 | 권한 | 설명 | 접근 범위 |
|---|---|---|---|
| 총괄 관리자 | ROLE_SUPER_ADMIN (안) | 관리자 계정 관리 | 전체 |
| 운영 관리자 | ROLE_OPERATOR (안) | 회원·계좌·거래 운영 | 대시보드, 회원, 계좌, 거래, 대출·카드 조회, 이상거래 탐지, 실시간 모니터링 |
| 상품·고객지원 관리자 | ROLE_SERVICE (안) | 상품, 고객지원 | 대시보드, 상품, 고객지원 |
| 시스템 | 내부 | 판정, 계정 잠금, 지급정지 등 자동 처리 | 해당 도메인 |

> 역할 구분은 확정 전이다. 확정 전까지는 단일 ROLE_ADMIN으로 개발한다.

## 4. 범위

**포함**
- 관리자 전용 로그인과 권한
- 회원·계좌·거래·상품·대출·카드 조회
- 회원 이용 제한·잠금 해제, 계좌 동결/해제, 상품 등록·수정
- 계좌 상태 이력 조회, 관리자 활동 로그
- 공지·FAQ·1:1 문의 관리(관리자 화면)
- 룰 기반 이상거래 탐지, 실시간 모니터링 (구현 범위는 일정에 따라 추후 결정)

**제외**
- 회원가입 승인, 계좌 개설 승인, 이체한도 변경 승인, 대출 심사 판정 (시스템 규칙, 각 도메인 담당)
- 고객 화면 공통 레이아웃·CSS, 공통 응답 DTO·전역 예외 처리 (팀 공통)
- AI 기반 이상거래 판정

## 5. 요구사항 분석

### 5.1 전체 구조

```text
관리자 콘솔 (/admin)
├─ 관리자 인증 (로그인, 권한)
├─ 대시보드
├─ 회원 관리 ─────── 목록/검색, 상세, 이용 제한, 잠금 해제, 로그인 이력
├─ 계좌 관리 ─────── 목록/검색, 상세, 동결/해제, 상태 이력
├─ 거래 관리 ─────── 전체 거래내역, 이체내역
├─ 상품 관리 ─────── 예적금 등록/수정/판매중지
├─ 대출 관리 ─────── 신청·심사 결과 내역, 대출 현황
├─ 카드 관리 ─────── 발급 현황, 정지
├─ 고객지원 관리 ─── 공지, FAQ, 1:1 문의
├─ 감사 로그 ─────── 관리자 활동 로그
├─ 이상거래 탐지 ──── 탐지 규칙, 탐지 목록, 조치
├─ 실시간 모니터링 ─── 탐지 알림, 실시간 거래 현황, 대시보드 자동 갱신
└─ 관리자 계정 ───── 계정 발급, 권한 변경
```

### 5.2 관리자와 다른 도메인의 관계

```text
[고객]  → 해지 요청 ─────┐
[시스템] → 잠금/지급정지 ─┼─→ 각 도메인 상태 변경 서비스 ─→ 상태 변경 + 이력 기록
[관리자] → 동결/제한 ─────┘                                  └→ (관리자일 때) ADMIN_LOG
```

관리자는 다른 도메인 테이블을 직접 수정하지 않고 해당 도메인의 서비스를 호출한다.

## 9. 가정과 의존성

- 승인 판정은 각 도메인 시스템 규칙이 처리한다 (팀 합의 전제).
- 계좌 상태 변경은 팀원2가 만든 단일 서비스 메서드로만 한다.
- 계정 잠금·로그인 이력은 팀원1의 인증 모듈이 기록한다.
- 대출 판정 결과와 근거는 팀원3이 LOAN에 저장한다.
- 관리자 계정은 ADMIN 테이블 분리를 가정한다 (팀원1과 확정 필요).
- FDS는 팀원2의 이체 완료 이벤트를 받아 동작한다 (이벤트 방식은 팀원2와 협의).
- Redis는 판정용 집계값만 담고, 거래 원장은 DB가 기준이다.
- 고객과의 실제 연락(전화)은 시스템 밖에서 하고, 시스템은 연락 결과만 기록한다.
- 고객 화면 안내(FDS-007)는 고객 알림 기능 담당과 협의한다.
