# 모의 인터넷뱅킹 관리자 파트 기능명세서

## 문서 이력

| 버전 | 작성일 | 작성자 | 변경 내용 |
|---|---|---|---|
| v0.1 | 2026-10-02 | (작성자) | 최초 작성, 핵심 기능 상세 10개 |
| v0.2 | 2026-10-02 | (작성자) | FDS·MON 기능 목록 갱신, 상세 2개(FDS-001, MON-001), FDS_DETECTION 테이블 추가 |
| v0.3 | 2026-10-02 | (작성자) | 이상거래 대응 흐름 추가, 상세 2개(FDS-005, MON-005), 알림·처리 이력 테이블 추가 |

## 작성 규칙

- 기능 ID: `FUNC-ADM-서비스-번호` (요구사항 ID `FR-ADM-서비스-번호`와 번호를 맞춤)
- API 주소, 테이블 컬럼은 초안. ERD·API 명세 확정 시 함께 수정
- "협의" 표시는 다른 파트와 정해야 하는 부분

## 공통 사항

- 모든 관리자 API는 `/api/admin/**`, 화면은 `/admin/**`
- 응답은 팀 공통 응답 형식 사용
- 상태를 바꾸는 기능은 공통 처리 순서를 따른다:
  1. 관리자 권한 확인 → 2. 대상 현재 상태 확인 → 3. 해당 도메인 서비스로 상태 변경 → 4. ADMIN_LOG 기록 → 5. COMMIT (중간 실패 시 전체 롤백)
- 상태 변경에는 사유 입력이 필수
- 목록 화면은 검색 조건 + 페이징(기본 20건) + 최신순

## 2. 기능 상세

### 2.1 FUNC-ADM-AUT-001 관리자 로그인

| 항목 | 내용 |
|---|---|
| 연결 요구사항 | FR-ADM-AUT-001 |
| 사용자/권한 | 관리자 (비로그인 상태) |
| 사전 조건 | 활성 상태 관리자 계정 존재 |
| 입력 항목 | 관리자 아이디(필수), 비밀번호(필수) |
| 처리 로직 | 1. 관리자 계정 조회 (ADMIN 테이블) → 2. 활성 상태 확인 → 3. 비밀번호 비교 → 4. 성공 시 관리자 세션 생성, 마지막 로그인 일시 갱신 → 5. 실패 시 실패 횟수 증가, 5회면 잠금 |
| 출력/결과 | 관리자 대시보드로 이동 |
| 예외 처리 | 불일치 → "아이디 또는 비밀번호가 올바르지 않습니다" / 비활성·잠금 → "사용할 수 없는 계정입니다" / 고객 계정 입력 → 불일치와 같은 메시지 |
| 사후 조건 | 관리자 세션 생성 |
| 관련 화면 | 관리자 로그인 |
| 관련 API | `POST /admin/login` (Spring Security) |
| 관련 테이블 | ADMIN |
| 비고 | ADMIN 테이블 분리, 별도 SecurityFilterChain 구성은 팀원1과 협의 |

| 관련 테이블 | ACCOUNT, ACCOUNT_STATUS_HISTORY, ADMIN_LOG |
| 비고 | 상태 변경 서비스와 이력 테이블은 팀원2 소유 (협의). 동결 중 입금 허용 여부도 협의 |

## 3. 관련 테이블 초안

> 관리자 파트가 소유하거나 직접 설계에 참여하는 테이블. ERD 확정 시 수정.

```text
ADMIN                       (관리자 소유, 팀원1 협의)
 ├─ ADMIN_ID
 ├─ LOGIN_ID
 ├─ PASSWORD
 ├─ NAME
 ├─ ROLE            (SUPER_ADMIN / OPERATOR / SERVICE, 확정 전에는 ADMIN 하나)
 ├─ STATUS          (활성 / 비활성 / 잠금)
 ├─ LOGIN_FAIL_COUNT
 ├─ LAST_LOGIN_AT
 └─ CREATED_AT

ADMIN_LOG                   (관리자 소유)
 ├─ LOG_ID
 ├─ ADMIN_ID
 ├─ ACTION_TYPE
 ├─ TARGET_TYPE     (MEMBER / ACCOUNT / PRODUCT / CARD ...)
 ├─ TARGET_ID
 ├─ BEFORE_VALUE
 ├─ AFTER_VALUE
 ├─ REASON
 ├─ REQUEST_IP
 └─ CREATED_AT

FDS_DETECTION               (관리자 소유)
 ├─ DETECTION_ID
 ├─ TRANSFER_ID
 ├─ ACCOUNT_ID
 ├─ RULE_CODE       (규칙 구분)
 ├─ DETAIL          (판정 근거: 횟수, 금액 등)
 ├─ STATUS          (미확인 / 담당 확인 / 고객 연락 중 / 정상 거래 확인 / 사기 의심 조치)
 ├─ ASSIGNED_TO     (담당 관리자)
 ├─ ASSIGNED_AT
 ├─ CLOSED_AT
 └─ DETECTED_AT

FDS_HANDLING_HISTORY        (관리자 소유)
 ├─ HISTORY_ID
 ├─ DETECTION_ID
 ├─ ADMIN_ID
 ├─ STAGE           (변경된 단계)
 ├─ MEMO
 ├─ CONTACT_AT      (고객 연락 일시, 연락 단계에서만)
 ├─ CONTACT_METHOD  (전화 등)
 ├─ CONTACT_RESULT  (본인 거래 확인 / 본인 아님 / 연락 안 됨)
 └─ CREATED_AT

ADMIN_NOTIFICATION          (관리자 소유)
 ├─ NOTIFICATION_ID
 ├─ ADMIN_ID        (받는 관리자)
 ├─ TYPE            (FDS_DETECTED 등)
 ├─ TARGET_ID       (탐지 ID 등)
 ├─ MESSAGE
 ├─ READ_AT
 └─ CREATED_AT

ACCOUNT_STATUS_HISTORY      (팀원2 소유, 관리자가 조회)
 ├─ HISTORY_ID
 ├─ ACCOUNT_ID
 ├─ BEFORE_STATUS
 ├─ AFTER_STATUS
 ├─ CHANGED_BY_TYPE (CUSTOMER / SYSTEM / ADMIN)
 ├─ CHANGED_BY_ID
 ├─ REASON
 └─ CHANGED_AT
```
