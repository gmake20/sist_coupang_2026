# 상품 관련 테이블 쿼리 모음

`CreataTableDDL.md`(테이블 생성 DDL)와 `테이블_생성_및_상품등록_신창만.md`(등록/조회 쿼리)에
흩어져 있던 **상품(PRODUCT) 관련 쿼리만** 한 곳에 모은 문서입니다.
회원/판매자 가입, 관리자 승인, DB 백업·복원 등 상품과 무관한 내용은 제외했습니다.

⚠ `PRODUCT`/`PRODUCT_OPTION`은 화면(`vendor_product_write.jsp`) 입력 항목을 전부 담기 위해
기존 스키마보다 컬럼이 많이 늘어난 버전입니다. 기존 DB에 두 테이블이 이미 있다면
맨 아래 "8. 초기화" 절의 DROP문으로 지우고 다시 만들어야 합니다.

⚠ **2026-08-23 재검증**: 이 문서의 샘플 INSERT들이 쓰던 `sub_category_no`(100301, 100101, 110101,
100202, 110103)는 실제로 존재하는 값이 아니었습니다. `docs/category_table_create.sql`/
`category_table_insert.sql`을 직접 열어서 확인해보니, 실제 카테고리 번호 체계는
대분류 1~2자리(예: 4=식품) → 중분류 3자리(예: 406=생수/음료) → 소분류 5자리
(예: 40601=생수, 중분류 앞 3자리 + 소분류 2자리)로 되어 있어서 완전히 다른 숫자였습니다.
아래 INSERT들은 전부 실제 존재하는 소분류 번호로 고쳤습니다 (매핑은 아래 표 참고). FK
제약(`FK_CATEGORY_TO_PRODUCT`)이 걸려있어서, 예전 번호 그대로 실행했다면 전부 에러가 났을 겁니다.

| 상품 | 예전(존재하지 않던) sub_category_no | 실제 sub_category_no | 실제 카테고리 경로 |
|---|---|---|---|
| 남성 반팔 티셔츠 / 골프 이너웨어 | 100301 | **10301** | 패션의류/잡화 > 남녀 공용 의류 > 티셔츠 |
| 여성 롱패딩 | 100101 | **10308** ⚠ | 패션의류/잡화 > 남녀 공용 의류 > 아우터 (여성패션 하위엔 "의류"만 있고 아우터 전용 리프가 없어서 남녀공용 쪽으로 매핑함 — 팀 확인 필요) |
| 생수 2L(6입) | 110101 | **40601** | 식품 > 생수/음료 > 생수 |
| 남성 운동화 | 100202 | **10202** | 패션의류/잡화 > 남성패션 > 신발 |
| 벌꿀 | 110103 | **41205** ⚠ | 식품 > 가루/조미료/오일 > 천연조미료 (꿀 전용 리프가 카테고리 데이터에 없어서 가장 가까운 항목으로 임시 매핑함 — 팀 확인 필요) |

## 2. CATEGORY (선행 테이블 — PRODUCT.sub_category_no가 참조)

`카테고리_재귀테이블_테스트.md`에서 만든 자기참조(재귀) 카테고리 테이블과 동일합니다.
이미 DB에 만들어 두셨다면 이 절은 건너뛰어도 됩니다. `admin_no`는 `ADMIN` 테이블에 있는 값을
참조하므로, `ADMIN`에 데이터가 먼저 있어야 합니다.

```sql
CREATE TABLE CATEGORY (
    category_no          NUMBER(10)    NOT NULL, /* 카테고리 번호 (PK) */
    category_name        VARCHAR2(50)  NOT NULL, /* 카테고리명 */
    parent_category_no   NUMBER(10),             /* 상위 카테고리 번호. 최상위(대분류)는 NULL */
    category_level       NUMBER(1)     NOT NULL, /* 깊이: 1=대분류, 2=중분류, 3=소분류, 4=세분류 ... */
    created_date          DATE          NOT NULL, /* 등록일 */
    admin_no              NUMBER(10)    NOT NULL  /* 등록한 관리자 번호 */
);

CREATE UNIQUE INDEX PK_CATEGORY
    ON CATEGORY (category_no ASC);

ALTER TABLE CATEGORY
    ADD CONSTRAINT PK_CATEGORY
        PRIMARY KEY (category_no);

-- 자기참조 FK: 내 부모 카테고리도 결국 CATEGORY 테이블의 한 행
ALTER TABLE CATEGORY
    ADD CONSTRAINT FK_CATEGORY_TO_CATEGORY
        FOREIGN KEY (parent_category_no)
        REFERENCES CATEGORY (category_no);

ALTER TABLE CATEGORY
    ADD CONSTRAINT FK_ADMIN_TO_CATEGORY
        FOREIGN KEY (admin_no)
        REFERENCES ADMIN (admin_no);

-- 같은 부모 밑에 같은 이름의 카테고리가 중복 생성되는 것 방지
ALTER TABLE CATEGORY
    ADD CONSTRAINT UQ_CATEGORY_NAME
        UNIQUE (parent_category_no, category_name);
```

카테고리는 지금까지 `카테고리_메뉴_데이터_Insert.md` 등에서 category_no를 직접 지정해서
넣어왔기 때문에 시퀀스 없이도 동작합니다. 그래도 앞으로 애플리케이션에서 카테고리를 직접
등록하게 하려면 `SEQ_CATEGORY`(위 1절)를 쓰면 됩니다.

⚠ `PRODUCT`를 이미 만들어 둔 DB라면(위 CREATE TABLE을 다시 실행하지 않는다면), `display_yn` 컬럼이 없으니 아래 ALTER TABLE을 대신 실행하세요. 기존 상품 행은 전부 `display_yn='Y'`(노출)로 채워집니다.

```sql
ALTER TABLE PRODUCT ADD display_yn CHAR(1) DEFAULT 'Y' NOT NULL;

ALTER TABLE PRODUCT ADD CONSTRAINT CK_PRODUCT_DISPLAY_YN
    CHECK (display_yn IN ('Y', 'N'));
```

판매자가 상품을 "삭제"하면 실제로는 `UPDATE PRODUCT SET display_yn = 'N' WHERE product_no = ? AND seller_no = ?`만 실행됩니다(하드 삭제 아님). `ORDER_DETAIL.product_no`가 이미 그 상품을 참조하고 있는 기존 주문/리뷰는 영향 없고, 판매자센터 상품 목록 조회 쿼리에서만 `display_yn = 'Y'` 조건으로 걸러서 안 보이게 합니다.

**적용 방법**: 이 프로젝트는 마이그레이션 도구 없이, 이 문서에 SQL을 적어두면 팀원이 직접 DB에 접속해서 실행하는 방식입니다. 접속 정보는 `project/GoodPang/src/main/webapp/META-INF/context.xml`의 `jdbc/myoracle` 리소스에 있습니다(공용 Oracle DB, `scym3.cafe24.com/XEPDB1`). SQL Developer나 DBeaver 등으로 그 정보로 접속해서 위 ALTER TABLE 두 줄만 실행하면 됩니다. 계정 정보는 보안상 이 문서에 다시 옮겨 적지 않았으니 context.xml을 직접 확인하세요.

⚠ 2026-08-28 기준: 이 ALTER TABLE은 아직 실제 DB에 반영되지 않았습니다 (코드는 `display_yn` 컬럼이 있다는 전제로 이미 작성돼 있음 — `ProductListDAO`, `VendorProductDetailDAO`, `VendorProductWriteServlet` 관련 기능을 쓰기 전에 반드시 먼저 실행해야 합니다).

## 8. 초기화 (다시 만들 때만 실행)

자식 테이블부터 지워야 FK 에러가 안 납니다. `STOCK_HISTORY`가 기존 `PRODUCT_OPTION.OPTION_ID`를
참조하고 있다면 `PRODUCT_OPTION`보다 먼저 같이 정리해야 합니다.

```sql
DROP TABLE PRODUCT_NOTICE   CASCADE CONSTRAINTS PURGE;
DROP TABLE PRODUCT_TAG      CASCADE CONSTRAINTS PURGE;
DROP TABLE PRODUCT_IMAGE    CASCADE CONSTRAINTS PURGE;
-- STOCK_HISTORY가 PRODUCT_OPTION을 참조 중이면 여기서 같이 정리
-- DROP TABLE STOCK_HISTORY CASCADE CONSTRAINTS PURGE;
DROP TABLE PRODUCT_OPTION   CASCADE CONSTRAINTS PURGE;
DROP TABLE PRODUCT          CASCADE CONSTRAINTS PURGE;
-- CATEGORY는 PRODUCT가 참조하므로 PRODUCT보다 먼저 지우면 안 됨
-- 이미 만들어 둔 CATEGORY 데이터를 유지하고 싶다면 아래 두 줄은 실행하지 마세요
DROP TABLE CATEGORY         CASCADE CONSTRAINTS PURGE;

DROP SEQUENCE SEQ_CATEGORY;
DROP SEQUENCE SEQ_PRODUCT_IMAGE;
DROP SEQUENCE SEQ_PRODUCT_TAG;
DROP SEQUENCE SEQ_PRODUCT_NOTICE;
DROP SEQUENCE SEQ_PRODUCT;
DROP SEQUENCE SEQ_OPTION;
DROP SEQUENCE SEQ_PRODUCT_IN;
DROP SEQUENCE SEQ_STOCK_HISTORY;
```

## 11. 상품 입고 (프로시저 · 트리거)

⚠ `UP_PRODUCT_IN`은 `OPTION_ID` 기준이라, 옵션이 아예 없는 상품(`option_yn='N'`)에는
쓸 수 없습니다. 그런 상품은 `UPDATE PRODUCT SET quantity = quantity + 수량 WHERE product_no = ...`
로 직접 처리하세요.

```sql
-- 상품입고 프로시저
CREATE OR REPLACE PROCEDURE UP_PRODUCT_IN (
-- 신창만
-- 입고 프로시저. 옵션번호와 수량을 입력하면 해당 상품이 입고된다.
-- 사용법 : EXEC UP_PRODUCT_IN(옵션번호, 수량);
    P_OPTION_NO IN PRODUCT_IN.OPTION_ID%TYPE,
    P_QUANTITY  IN PRODUCT_IN.QUANTITY%TYPE
) IS
BEGIN
    INSERT INTO PRODUCT_IN
    VALUES (SEQ_PRODUCT_IN.NEXTVAL, P_QUANTITY, SYSDATE, P_OPTION_NO);

    COMMIT;
END;
/

-- 입고 시 옵션 재고를 자동으로 올려주는 트리거
CREATE OR REPLACE TRIGGER TRG_PRODUCT_IN_STOCK
AFTER INSERT ON PRODUCT_IN FOR EACH ROW
BEGIN
    UPDATE PRODUCT_OPTION
    SET QUANTITY = QUANTITY + :NEW.QUANTITY, STATUS = 'Y'
    WHERE OPTION_ID = :NEW.OPTION_ID;
END;
/

-- 사용 예시
-- 아래 쿼리로 옵션번호부터 확인
SELECT * FROM PRODUCT_OPTION WHERE product_no = (SELECT MAX(product_no) FROM PRODUCT);

EXEC UP_PRODUCT_IN(28, 5);
```


## 12. 상품 조회 (목록 · 카테고리 · 재고현황)

```sql
-- 1번 판매자가 등록한 상품조회
-- (자기참조 CATEGORY를 3번 셀프조인: c1=대분류, c2=중분류, c3=소분류)
SELECT p.*,
       s.store_name,
       c1.category_name AS main_category_name,
       c2.category_name AS mid_category_name,
       c3.category_name AS sub_category_name
FROM PRODUCT p
    JOIN SELLER s
      ON p.seller_no = s.seller_no
    JOIN CATEGORY c3
      ON p.sub_category_no = c3.category_no
    LEFT JOIN CATEGORY c2
      ON c2.category_no = c3.parent_category_no
    LEFT JOIN CATEGORY c1
      ON c1.category_no = c2.parent_category_no
WHERE p.seller_no = 1;

-- 1번 판매자의 각 상품별 재고 현황조회
SELECT p.product_no, p.product_name, p.product_desc, p.product_price,
       po.normal_price   AS option_normal_price,
       po.PRICE          AS option_sale_price,
       po.quantity       AS option_quantity,
       po.OPTION_ID,
       po.OPTION1_TYPE,
       po.OPTION1_VALUE,
       po.OPTION2_TYPE,
       po.OPTION2_VALUE,
       po.OPTION3_TYPE,
       po.OPTION3_VALUE,
       po.STATUS         AS option_status
FROM PRODUCT p
JOIN SELLER s
  ON p.seller_no = s.seller_no
LEFT JOIN PRODUCT_OPTION po
  ON p.product_no = po.product_no
WHERE p.seller_no = 1;

-- 카테고리보기 (대/중/소분류 트리)
SELECT c1.category_no   AS main_category_no,
       c1.category_name AS main_category_name,
       c2.category_no   AS mid_category_no,
       c2.category_name AS mid_category_name,
       c3.category_no   AS sub_category_no,
       c3.category_name AS sub_category_name
FROM CATEGORY c1
    LEFT JOIN CATEGORY c2 ON c2.parent_category_no = c1.category_no AND c2.category_level = 2
    LEFT JOIN CATEGORY c3 ON c3.parent_category_no = c2.category_no AND c3.category_level = 3
WHERE c1.category_level = 1
ORDER BY c1.category_no, c2.category_no, c3.category_no;

-- QA를 위한 카테고리별 상품갯수
SELECT c1.category_no   AS main_category_no,
       c1.category_name AS main_category_name,
       c2.category_no   AS mid_category_no,
       c2.category_name AS mid_category_name,
       c3.category_no   AS sub_category_no,
       c3.category_name AS sub_category_name,
       COUNT(p.product_no) AS product_count
FROM CATEGORY c1
    LEFT JOIN CATEGORY c2 ON c2.parent_category_no = c1.category_no AND c2.category_level = 2
    LEFT JOIN CATEGORY c3 ON c3.parent_category_no = c2.category_no AND c3.category_level = 3
    LEFT JOIN PRODUCT p ON c3.category_no = p.sub_category_no
WHERE c1.category_level = 1
GROUP BY c1.category_no, c1.category_name,
         c2.category_no, c2.category_name,
         c3.category_no, c3.category_name
ORDER BY c1.category_no, c2.category_no, c3.category_no;

-- 카테고리별로 상품보기
SELECT p.product_no,
       p.product_name,
       p.product_price,
       p.quantity,
       p.seller_no,
       c.category_name AS sub_category_name
FROM PRODUCT p
    JOIN CATEGORY c ON p.sub_category_no = c.category_no
WHERE p.sub_category_no = 10202; -- 소분류번호 (예: 남성패션 > 신발)

-- 1번 상품 조회 (옵션 있는 상품 + 옵션 없는 상품 모두 커버)
-- LEFT JOIN이라 옵션이 없는 상품(option_yn='N')도 나오고, 그럴 땐 NVL이 product_price/quantity로 대체함
SELECT
    S.STORE_NAME,
    P.PRODUCT_NO,
    P.product_name,
    O.OPTION_ID,
    O.OPTION1_TYPE,
    O.OPTION1_VALUE,
    O.OPTION2_TYPE,
    O.OPTION2_VALUE,
    O.OPTION3_TYPE,
    O.OPTION3_VALUE,
    NVL(O.PRICE, P.product_price)    AS 판매가,
    NVL(O.QUANTITY, P.quantity)   AS 재고,
    O.STATUS                          AS 판매여부
FROM PRODUCT P
JOIN SELLER  S ON P.SELLER_NO  = S.SELLER_NO
LEFT JOIN PRODUCT_OPTION O ON O.PRODUCT_NO = P.PRODUCT_NO
WHERE P.PRODUCT_NO = 1
ORDER BY O.PRODUCT_NO, O.OPTION_ID;
```


## 13. 상품문의 (프로시저 · 조회)

`PRODUCT_INQUIRY`/`PRODUCT_INQUIRY_ANSWER` 테이블 자체의 DDL은 이 문서 범위 밖(다른 팀원 문서)이라
없지만, `OPTION_ID`를 참조하는 상품 관련 기능이라 여기 같이 모아둡니다.

```sql
CREATE OR REPLACE PROCEDURE PROUDCT_QUESTION (
-- 상품문의
-- 사용법 : EXEC PROUDCT_QUESTION(상품옵션번호, 회원번호, 문의내용);
-- 신창만
    P_OPTION_ID         IN PRODUCT_INQUIRY.OPTION_ID%TYPE,
    P_MEMBER_NO         IN PRODUCT_INQUIRY.MEMBER_NO%TYPE,
    P_INQUIRY_CONTENT   IN PRODUCT_INQUIRY.INQUIRY_CONTENT%TYPE
) IS
BEGIN
    INSERT INTO PRODUCT_INQUIRY (inquiry_no, inquiry_content, inquiry_date, member_no, OPTION_ID)
    VALUES (SEQ_PRODUCT_INQUIRY.NEXTVAL, P_INQUIRY_CONTENT, SYSDATE, P_MEMBER_NO, P_OPTION_ID);

    COMMIT;
END;
/

CREATE OR REPLACE PROCEDURE PROUDCT_ANSWER (
-- 상품답변
-- 사용법 : EXEC PROUDCT_ANSWER (문의번호, 판매자번호, 답변내용);
-- 신창만
    P_INQUIRY_NO        IN PRODUCT_INQUIRY_ANSWER.INQUIRY_NO%TYPE,
    P_SELLER_NO         IN PRODUCT_INQUIRY_ANSWER.SELLER_NO%TYPE,
    P_INQUIRY_CONTENT   IN PRODUCT_INQUIRY_ANSWER.ANSWER_CONTENT%TYPE
) IS
BEGIN
    INSERT INTO PRODUCT_INQUIRY_ANSWER (answer_no, answer_content, answer_date, inquiry_no, seller_no)
    VALUES (SEQ_PRODUCT_INQUIRY_ANSWER.NEXTVAL, P_INQUIRY_CONTENT, SYSDATE, P_INQUIRY_NO, P_SELLER_NO);

    COMMIT;
END;
/

-- 사용법
EXEC PROUDCT_QUESTION(상품옵션번호, 회원번호, 문의내용);
EXEC PROUDCT_ANSWER (문의번호, 판매자번호, 답변내용);

-- 문의내역보기
SELECT po.OPTION_ID,
       pi.inquiry_no,
       pi.inquiry_content,
       pi.inquiry_date,
       pi.member_no,
       pia.answer_no,
       pia.answer_content,
       pia.answer_date,
       pia.seller_no
FROM PRODUCT_OPTION po
    JOIN PRODUCT_INQUIRY pi ON po.OPTION_ID = pi.OPTION_ID
    LEFT JOIN PRODUCT_INQUIRY_ANSWER pia ON pi.inquiry_no = pia.inquiry_no
WHERE po.product_no = 상품번호
ORDER BY po.OPTION_ID, pi.inquiry_date;
```
