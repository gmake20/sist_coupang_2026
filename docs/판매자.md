## 판매자(SELLER) 테이블 DDL

`docs/capture/쿠팡판매자/쿠팡판매자회원가입/` 캡처(cap1~cap13)로 확인한 실제 쿠팡윙 입점 흐름
(계정생성 → 카테고리선택 → 사업자정보입력[사업장주소·통신판매업신고·정산계좌·서류첨부] →
입점심사[대기/진행중/완료])과, 현재 구현된 `vendor-signup.jsp`(계정정보+사업자 기본정보를
한 화면에서 한 번에 받는 축약형)를 기준으로 설계했습니다. AML 고객확인제도(cap9~12, 대표자
실명확인·거래정보확인)는 금융규제 대응용 심화 기능이라 이 프로젝트 범위에서는 제외했습니다.

⚠ `old_project/최종_쿼리_취합.md`의 기존 SELLER 테이블은 `seller_id`/`email`을 별도 컬럼으로
뒀지만, 실제 `vendor-signup.jsp`엔 "아이디(이메일)" 필드 하나뿐이고 `LoginServlet`도 이메일로
조회하므로 `email` 하나를 로그인 아이디로 통합했습니다. 또한 기존 테이블엔 없던 담당자명·
사업자유형·서류첨부·입점심사상태·등록일 컬럼을 추가했습니다.

`vendor-signup.jsp`에서 이미 받는 항목(이메일/비밀번호/담당자명/대표자명/상호/사업자등록번호/
사업자유형/휴대폰)은 NOT NULL로, 아직 화면이 없는 항목(사업장주소/통신판매업신고번호/대표카테고리/
정산계좌/서류첨부)은 NULL 허용으로 두고 이후 단계(1-3·1-4)에서 UPDATE하는 구조입니다.

⚠ **2026-08-25 재검증**: `approval_status`를 처음엔 `VARCHAR2(10)`으로 만들었다가 실제 INSERT
시 `ORA-12899` 오류가 났습니다. Oracle `VARCHAR2(n)`은 글자수가 아니라 **바이트수** 기준인데
`'입점 대기'`가 한글4자×3바이트+공백1바이트=13바이트라 10바이트를 초과했기 때문입니다. `PRODUCT.sale_status`
등 다른 상태 컬럼들처럼 `VARCHAR2(20)`으로 넓혀서 해결했습니다(아래 DDL에 반영됨). 앞으로 한글이 들어가는
컬럼 길이를 잡을 때는 글자수 × 3바이트로 여유 있게 잡아야 합니다.

```sql
CREATE SEQUENCE SEQ_SELLER START WITH 1 INCREMENT BY 1 NOCACHE;

CREATE TABLE SELLER (

    /* 계정정보 — vendor-signup.jsp 1단계에서 즉시 INSERT */
    seller_no                  NUMBER(10)    NOT NULL, /* 판매자번호 (PK) */
    email                       VARCHAR2(100) NOT NULL, /* 로그인 아이디로 사용하는 이메일 */
    seller_pw                  VARCHAR2(100) NOT NULL, /* 비밀번호 (BCrypt 해시) */
    manager_name                VARCHAR2(30)  NOT NULL, /* 입점 담당자명 (vendor-signup.jsp의 managerName) */
    phone                       VARCHAR2(20)  NOT NULL, /* 휴대폰번호 */

    /* 사업자 기본정보 — vendor-signup.jsp 1단계에서 같이 받음 */
    business_no                 VARCHAR2(20)  NOT NULL, /* 사업자등록번호 */
    business_type                VARCHAR2(20)  NOT NULL, /* 사업자유형: 개인사업자/법인사업자 */
    ceo_name                     VARCHAR2(30)  NOT NULL, /* 대표자명 */
    store_name                   VARCHAR2(100) NOT NULL, /* 상호명 */

    /* 사업자 상세정보 — 아직 화면 없음(1-3·1-4에서 UPDATE 예정) */
    zipcode                      VARCHAR2(10),            /* 사업장 우편번호 */
    business_address             VARCHAR2(200),           /* 사업장 기본주소 */
    business_detail_address      VARCHAR2(200),           /* 사업장 상세주소 */
    mail_order_no                 VARCHAR2(50),            /* 통신판매업신고번호 */
    category_no                   NUMBER(10),              /* 대표 판매 카테고리 (CATEGORY, 대분류) */

    /* 정산계좌 — 1-3에서 UPDATE 예정 */
    bank_name                    VARCHAR2(30),            /* 은행명 */
    account_no                    VARCHAR2(50),            /* 계좌번호 */
    account_holder                VARCHAR2(30),            /* 예금주명 */

    /* 서류첨부 — 1-4에서 UPDATE 예정. 실제 파일은 webapp/upload/에 저장하고 경로만 기록 */
    business_cert_url             VARCHAR2(500),           /* 사업자등록증 이미지 경로 */
    mail_order_cert_url            VARCHAR2(500),           /* 통신판매신고증 이미지 경로 */

    /* 입점심사 — 2번(입점 심사 상태) 대응 */
    approval_status               VARCHAR2(20)  NOT NULL, /* 입점 대기/심사 중/승인/반려/정지 */
    reject_reason                  VARCHAR2(500),           /* 반려 사유 (반려 시에만 기록) */
    approved_admin_no              NUMBER(10),              /* 승인/반려 처리한 관리자 (ADMIN) */
    approved_date                  DATE,                    /* 승인/반려 처리일 */

    /* 메타 */
    created_date                   DATE          NOT NULL, /* 가입일 */
    updated_date                   DATE          NOT NULL  /* 수정일 */
);

CREATE UNIQUE INDEX PK_SELLER
    ON SELLER (seller_no ASC);

ALTER TABLE SELLER
    ADD CONSTRAINT PK_SELLER PRIMARY KEY (seller_no);

-- 이메일(로그인 아이디) 중복가입 방지
ALTER TABLE SELLER
    ADD CONSTRAINT UQ_SELLER_EMAIL UNIQUE (email);

-- 같은 사업자등록번호로 중복 입점신청 방지
ALTER TABLE SELLER
    ADD CONSTRAINT UQ_SELLER_BUSINESS_NO UNIQUE (business_no);

ALTER TABLE SELLER
    ADD CONSTRAINT FK_CATEGORY_TO_SELLER
        FOREIGN KEY (category_no) REFERENCES CATEGORY (category_no);

ALTER TABLE SELLER
    ADD CONSTRAINT FK_ADMIN_TO_SELLER
        FOREIGN KEY (approved_admin_no) REFERENCES ADMIN (admin_no);

ALTER TABLE SELLER ADD CONSTRAINT CK_SELLER_BUSINESS_TYPE
    CHECK (business_type IN ('개인사업자', '법인사업자'));

ALTER TABLE SELLER ADD CONSTRAINT CK_SELLER_APPROVAL_STATUS
    CHECK (approval_status IN ('입점 대기', '심사 중', '승인', '반려', '정지'));
```

⚠ **2026-09-03 추가**: 문제 있는 판매자 계정을 정지시키는 기능을 위해 `'정지'` 상태를 추가했습니다.
이미 테이블이 만들어진 상태라면 아래 ALTER로 제약을 다시 걸어야 합니다 (기존 CHECK 삭제 후 재생성).
```sql
ALTER TABLE SELLER DROP CONSTRAINT CK_SELLER_APPROVAL_STATUS;
ALTER TABLE SELLER ADD CONSTRAINT CK_SELLER_APPROVAL_STATUS
    CHECK (approval_status IN ('입점 대기', '심사 중', '승인', '반려', '정지'));
```

| 상호(회사명) | SELLER.store_name | |
