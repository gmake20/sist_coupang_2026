# 🏦 은행 웹 프로젝트 실행 계획 및 핵심 가이드 > **프로젝트 기간:** 2주 반 (약 17일) > **팀 구성:** 4명 (경력자 2명 + 초보자 2명) > **주요 목표:** 핵심 금융 서비스 흐름(Happy Path)을 완벽하게 완성하여 포트폴리오 가치를 극대화하기 --- ## 1. 주요 기능 구현 범위 및 현실적 대안 실제 외부 API 연동이나 C/C++ 기반 보안 모듈 개발은 제한된 기간(2주 반)을 고려해 **모의(Mock) 방식**으로 구현합니다. ### ① 신분증 인증 (OCR & 진위확인) * **실제 은행 동작:** 신분증 촬영 $\rightarrow$ Naver Cloud OCR / Upstage / 금융결제원 API로 텍스트 추출 $\rightarrow$ 정부24·경찰청 DB 연동 진위 확인 * **우리의 구현 방식 (Mocking):** * **UI/UX:** 신분증 이미지 파일 업로드 폼 제작 $\rightarrow$ 업로드 시 **"신분증 진위 확인이 완료되었습니다"** 팝업/성공 페이지 전환 * **백엔드 검증:** 주민등록번호 형식(숫자 13자리)만 백엔드 DTO Validator(`@Pattern` 등)로 형식 검증 처리 ### ② 타행 계좌 인증 (1원 송금 인증) * **실제 은행 동작:** 오픈뱅킹 API / PG사 API 사용 $\rightarrow$ 1원 입금 및 입금자명에 4자리 인증번호 전송 $\rightarrow$ 사용자 입력 검증 * **우리의 구현 방식 (Mocking):** * **자체 모의 인증:** 유저가 입력한 가상 계좌로 백엔드가 **4자리 랜덤 난수(예: 1234)**를 생성하여 DB/Redis에 저장 * **안내 방식:** 화면에 **"등록하신 계좌로 1원과 인증번호가 발송되었습니다. (테스트용 인증번호: 1234)"** 문구 노출 또는 모의 입금내역 확인 페이지 제공 후 검증 ### ③ 은행 사이트의 '보안 프로그램 설치' 관련 * **실제 은행 동작:** Client-Side(ActiveX, PKI 모듈, Non-Plugin Executable) + C/C++ 프로그램 구동 * *키보드 보안 (E2E):* PC 입력 암호화 $\rightarrow$ 서버 측 대칭키/비대칭키(PKI) 복호화 * *공인/공동인증서:* PC의 NPKI 개인키 서명 $\rightarrow$ 서버 측 CA(발급기관) 검증 모듈로 유효성 체크 * **우리의 구현 방식:** * C/C++ 및 PKI 인프라 구축은 웹 프로젝트 범위를 벗어나므로 **구현 대상에서 제외** * **Spring Security + JWT/Session**, **HTTPS 적용(TLS 암호화)**, **비밀번호 암호화(`BCryptPasswordEncoder`)** 적용으로 웹 보안 기본 기틀 완비 --- ## 2. 효율적인 역할 분담 및 UI 전략 ### 👥 역할 분담 (경력 2명 / 초보 2명) * **경력자 (2명):** * Spring Boot 초기 환경 설정 (Spring Security, DB 스키마 설계, JPA/MyBatis 설정) * 공통 API 설계 및 규격화 * 고난도 비즈니스 로직 (계좌 이체 트랜잭션, 잔액 조회 Lock/동시성 처리 등) * **초보자 (2명):** * 회원가입 / 로그인 기본 CRUD * 게시판 (고객센터, FAQ, Q&A) * 마이페이지 조회 * 화면 UI 템플릿 적용 및 백엔드 연동 ### 🎨 UI / CSS 전략 * 맨땅에서 CSS를 작성하면 레이아웃 조정에 많은 시간이 소요됩니다. * **Bootstrap 5**, **Tailwind CSS**, **AdminLTE** 등 기존 UI 프레임워크/템플릿을 도입해 스타일만 일부 수정하는 방식을 권장합니다. --- ## 3. 기능 개발 우선순위 (Domain Priority) 1. **[1순위] 필수 핵심 기능 (Happy Path)** `회원가입/로그인` $\rightarrow$ `계좌 개설 (모의 신분증/1원 인증)` $\rightarrow$ `계좌 목록 조회 및 잔액 확인` $\rightarrow$ `계좌 이체 (트랜잭션 처리)` $\rightarrow$ `거래 내역 조회` 2. **[2순위] 부가 기능 (시간 남을 때 진행)** `대출 신청` / `적금 상품 가입` / `고객센터 게시판` / `Q&A` --- ## 💡 4. 추가 제안 사항 (프로젝트 완성도를 높이는 팁) | 구분 | 주요 내용 및 적용 방안 | | :--- | :--- | | **트랜잭션 & 동시성** | 계좌 이체 시 `@Transactional`을 적용하여 **송금자 차감과 수금자 가산이 하나의 단위**로 처리되도록 구현합니다.
