# 카테고리 재귀(자기참조) 테이블 테스트

기존 MAIN_CATEGORY / MID_CATEGORY / SUB_CATEGORY 3단계 고정 구조 대신,
카테고리를 하나의 테이블에서 parent_category_no로 자기참조하여
깊이 제한 없이(3단계든 5단계든) 표현하는 방식을 테스트하기 위한 샘플입니다.

기존 스키마를 건드리지 않는 별도 테스트용 테이블(CATEGORY)이므로
그냥 실행해서 붙여보고, 마음에 안 들면 DROP TABLE CATEGORY CASCADE CONSTRAINTS PURGE; 로 지우면 됩니다.

admin_no는 기존 ADMIN 테이블에 있는 값(예시로 1) 기준입니다. 없다면 admin_no NOT NULL 제약을 잠시 빼거나
실제 존재하는 admin_no로 바꿔서 실행하세요.

## 1. 테이블 생성 (DDL)

```sql
DROP TABLE CATEGORY CASCADE CONSTRAINTS PURGE;

CREATE TABLE CATEGORY (
    category_no          NUMBER(10)    NOT NULL, /* 카테고리 번호 (PK) */
    category_name        VARCHAR2(50)  NOT NULL, /* 카테고리명 */
    parent_category_no    NUMBER(10)    NULL,     /* 상위 카테고리 번호. 최상위(대분류)는 NULL */
    category_level        NUMBER(1)     NOT NULL, /* 깊이: 1=대분류, 2=중분류, 3=소분류, 4=세분류 ... */
    created_date          DATE          NOT NULL,
    admin_no              NUMBER(10)    NOT NULL
);

CREATE UNIQUE INDEX PK_CATEGORY
    ON CATEGORY (category_no ASC);

ALTER TABLE CATEGORY
    ADD CONSTRAINT PK_CATEGORY
        PRIMARY KEY (category_no);

-- 자기참조 FK: 내 부모 카테고리도 결국 CATEGORY 테이블의 한 행
ALTER TABLE CATEGORY
    ADD CONSTRAINT FK_CATEGORY_TO_CATEGORY
        FOREIGN KEY (parent_category_no)
        REFERENCES CATEGORY (category_no);

ALTER TABLE CATEGORY
    ADD CONSTRAINT FK_ADMIN_TO_CATEGORY
        FOREIGN KEY (admin_no)
        REFERENCES ADMIN (admin_no);

-- 같은 부모 밑에 같은 이름의 카테고리가 중복 생성되는 것 방지
ALTER TABLE CATEGORY
    ADD CONSTRAINT UQ_CATEGORY_NAME
        UNIQUE (parent_category_no, category_name);
```

## 2. 샘플 데이터 INSERT

캡처 화면(카테고리 검색 "귤")에 나온 예시 경로를 그대로 재현하도록 구성했습니다.
"가전디지털 > 계절가전 > 공기청정기" 3단계와, "식품 > 신선식품 > 과일류 > 과일 > 귤" 5단계가
같은 테이블 안에 섞여 들어갈 수 있다는 게 이 구조의 핵심입니다.

```sql
-- 1단계 (대분류)

INSERT INTO CATEGORY VALUES (3, '스포츠/레저', NULL, 1, SYSDATE, 1);

-- 2단계 (중분류)
INSERT INTO CATEGORY VALUES (11, '신선식품', 1, 2, SYSDATE, 1);
INSERT INTO CATEGORY VALUES (12, '생수/음료', 1, 2, SYSDATE, 1);
INSERT INTO CATEGORY VALUES (13, '계절가전', 2, 2, SYSDATE, 1);
INSERT INTO CATEGORY VALUES (14, '수영/수상스포츠', 3, 2, SYSDATE, 1);

-- 3단계 (소분류)
INSERT INTO CATEGORY VALUES (21, '과일류', 11, 3, SYSDATE, 1);
```

## 3. 조회 쿼리

### 3-1. 전체 트리 조회 (들여쓰기 + 전체경로)

```sql
SELECT LPAD(' ', (LEVEL - 1) * 2) || category_name AS category_tree,
       LEVEL                                        AS depth,
       SUBSTR(SYS_CONNECT_BY_PATH(category_name, '>'), 2) AS full_path,
       category_no,
       parent_category_no,
       CONNECT_BY_ISLEAF                             AS is_leaf   -- 1이면 더 이상 하위 카테고리 없는 말단
FROM CATEGORY
START WITH parent_category_no IS NULL
CONNECT BY PRIOR category_no = parent_category_no
ORDER SIBLINGS BY category_name;
```

### 3-2. 카테고리 검색 (캡처 화면의 "귤" 검색과 동일한 동작)

키워드가 포함된 카테고리를 찾아서, 그 카테고리의 대분류부터 이어지는 전체 경로를 함께 보여줍니다.
상품등록 화면의 "카테고리 검색" 탭이 정확히 이 쿼리 결과를 그대로 뿌려주면 됩니다.

```sql
SELECT full_path, category_no, depth
FROM (
    SELECT SUBSTR(SYS_CONNECT_BY_PATH(category_name, '>'), 2) AS full_path,
           category_no,
           category_name,
           LEVEL              AS depth,
           CONNECT_BY_ISLEAF  AS is_leaf
    FROM CATEGORY
    START WITH parent_category_no IS NULL
    CONNECT BY PRIOR category_no = parent_category_no
)
WHERE category_name LIKE '%' || '귤' || '%'
  AND is_leaf = 1        -- 상품은 보통 말단 카테고리에만 등록 가능하므로 리프만 노출
ORDER BY full_path;
```

### 3-3. 특정 카테고리의 하위 트리 전체 조회 (예: '식품' 하위 전부)

```sql
SELECT LEVEL AS depth,
       category_no,
       category_name,
       parent_category_no
FROM CATEGORY
START WITH category_no = 1          -- 1 = '식품'
CONNECT BY PRIOR category_no = parent_category_no
ORDER SIBLINGS BY category_name;
```

### 3-4. 직계 자식만 조회 (드롭다운/단계별 선택 UI용)

"카테고리 선택" 탭처럼 대분류 → 중분류 → 소분류를 한 단계씩 펼쳐서 고를 때 쓰는 쿼리입니다.

```sql
-- 최상위(대분류) 목록
SELECT category_no, category_name
FROM CATEGORY
WHERE parent_category_no IS NULL
ORDER BY category_name;

-- 특정 카테고리(예: 1='식품')의 바로 아래 자식만
SELECT category_no, category_name
FROM CATEGORY
WHERE parent_category_no = 1
ORDER BY category_name;
```

## 4. 정리

- `category_level` 컬럼은 필수는 아니지만(트리 순회로 깊이 계산 가능), 화면에 "N단계까지만 선택 가능" 같은
  제약을 걸거나 인덱스 검색을 빠르게 하고 싶을 때 있으면 편합니다.
- 상품(PRODUCT)이 참조할 카테고리는 항상 말단(리프) 카테고리여야 하므로, 등록 로직에서
  `CONNECT_BY_ISLEAF = 1`인 category_no만 선택 가능하도록 검증하면 됩니다.
- 이 테스트가 마음에 들면, 실제로 PRODUCT.sub_category_no를 CATEGORY.category_no로 교체하는 건
  기존 FK(FK_SUB_CATEGORY_TO_PRODUCT)와 SUB_CATEGORY 관련 쿼리를 전부 손봐야 하는 큰 작업이니
  별도로 마이그레이션 계획을 잡고 진행하는 걸 추천합니다.
